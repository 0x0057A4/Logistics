# Gemeinsamer Entwicklungsvertrag K00

Statisches ES-Modulspiel. Dateien dist/*.js. Keine externen Laufzeitabhängigkeiten. Deutsch. Root betreut UI und Integration. Eindeutige Dateien je Agent. Standard API wird vor Erweiterungen abgestimmt.

## Schnittstelle
`new Simulation({mode:'guided'|'economy'|'sandbox', seed:123})`, `.state`, `.command({type,...}) -> {ok:boolean,message?:string,id?:string}`, `.step(minutes=1)`, `.serialize() -> JSON string`, `Simulation.fromJSON(string)`, `.forecast(minutes,commands=[])` isolierte Kopie. Import aus `./core.js`. `.step(n)` zerlegt immer in n ganzzahlige Ein-Minuten-Schritte. Spielstart t=480 (08:00), ein Echtzeitsekunde = eine Spielminute. UI enthält keine Fachbuchungen.

Jedes Fachmodul exportiert `init(s)`, `handle(s,c,api)` (null bei unbekanntem Befehl), `step(s,api)` (ein Spielminute). `catalog.js` vom Produktionsagenten besitzt exportierte `ITEMS`, `BUILDINGS`, `RECIPES`, `ROLES`, `VEHICLES`, `RESEARCH` Objekte. Details in Katalog ohne Importabhängigkeiten. Keine fremden Dateien bearbeiten.

## Gemeinsamer Zustand
`schema:1, mode, seed, t:480, seq:1, money:85000, reputation:50, selectedSite:'site-1', sites:[{id:'site-1',name:'Werk Morgenfeld',x:0,y:0,width:20,height:16,energy:30}], buildings:[], workers:[], batches:[], reservations:[], jobs:[], purchases:[], orders:[], vehicles:[], shipments:[], ledger:[], events:[], research:[], rules:[], returns:[], stats:{produced:0,delivered:0,revenue:0,costs:0}, settings:{incidents:true}, milestones:[]`.
Keine Darstellungseigenschaften im Zustand nötig. IDs global `api.id(prefix)`; monoton sequenziell. `api.log(kind,text,refs=[])` Ereignis {id,t,kind,text,refs}, begrenzt auf 3000. Geld nur `api.book(key,amount,category,note,refs=[]) -> bool`, einmalig mittels ledger key. Geld Euro, Menge Stück, Zeit Minuten, Position Rasterzellen. Zustand JSON-rein.

## Modulzuständigkeit
- core.js: A03 Kern, Initialisierung, feste Schritte, PRNG `api.random()`, Speichern/Validieren, Bau/Wege (ggf separater world.js), Forschungs-/Regelerweiterungen später.
- inventory.js: A05 Chargen/Reservierung. api.inventory {add(spec),available(item,site,owner='company'),reserve(item,qty,site,job,owner='company'),release(job),consume(job),move(batchId,location,site?),used(site),capacity(site)}. `reserve` bool, `consume` Array verbrauchter Chargenteile oder false. add gibt Charge zurück. Charge {id,item,qty,site,owner,location:'stock'|'inbound'|'machine'|'vehicle'|'quarantine',quality:0..100,unitCost,parents:[],reserved:0}. Reservierung {id,batchId,qty,job}. Volumen/Gewicht zunächst Einheitspunkte. `capacity` Grundkapazität 40 + Regale. Nur stock + company + keine Sperre verfügbar.
- production.js + catalog.js + workforce.js: A04/A06 Maschinen/Produktion/Personal. Gebäude {id,type,site,x,y,rotation,status,progress,job:null,condition:100,recipe:null,enabled:true}; Jobs {id,building,recipe,remaining,duration,status,worker,inputs,output}. Personal {id,name,role,site,task:null,shift:'day'|'night'|'all',skill:1,fatigue:0,wage:...}. `api.workforce.acquire(role,site,task)` Person|null; `.release(task)`. Produktionsbefehle `setRecipe {id,recipe}`, `toggleBuilding {id}`, `hire {role,site}`, `fire {id}`, `train {id}`, `setShift {id,shift}`, `maintain {id}`. Automatische Fertigung freier Anlagen aus passendem Bestand; Wege-/Bereitstellzeit im Job. Pause/Schichtende unterbricht ohne Materialverlust. Montage -> Prüfung -> Verpackung. Grundrollen production,warehouse,driver,technician,service,research.
- economy.js + transport.js: A08/A07 Einkauf/Verträge/Fuhrpark. API economy.book siehe oben, Konten idempotent. `buy {item,qty,supplier:'standard'|'express'|'quality',site}` mit mindestens zwei getrennten Lieferungen möglich, echte Annahmezeit warehouse nötig. `acceptOrder {id}`, `dispatch {orderId,vehicleId,qty,site}`, `buyVehicle {vehicleType,site}`, `cancelOrder {id}`; angebotenes order {id,customer,item,qty,price,due,quality,site,status:'offer'|'active'|'fulfilled',delivered:0,paid:0}. Fahrzeuge {id,name,type,site,capacity,condition,status:'idle',shipment:null}. Shipment besitzt reservierte echte Ladung, loading/transit/unloading/returning, delayed payment nach Zustellung. Teilmengen; später Standorttransfers/Fremdeigentum/Sonderfracht. economy stellt api.book bereit durch export `book(s,key,amount,category,note,refs)`.
- scene.js: A09 Rendering rein aus Zustand. `new Scene(canvas,{onSelect(id),onPlace(x,y),onHover(x,y)})`, `.setState(s)`, `.setBuild(type|null,rotation=0)`, `.setView('hall'|'network'|'site'|'flat')`, `.zoom(delta)`, `.rotate()`, `.home()`, `.destroy()`. Eigene stilisierte Isometrie über Canvas polygonale Körper (robuster Ersatz); echte WebGL-Erweiterung wenn möglich. Funktionale Zellenpositionen/Personen/Transporte nur Zustand. Root integriert.
- app.js/index.html/styles.css: A01/A10. Baumodus, Fachpanels, Tutorial, Akten, Bedienung.
- tests/: A11 unabhängig. Keine Produktionsmodule verändern.

## Kernbau
Kern handles `build {buildingType,x,y,rotation,site}`, `move {id,x,y,rotation}`, `demolish {id}`. Katalog BUILDINGS pro Eintrag {name,cost,w:2,h:2,color,role,recipes:[],power:...}. Belegung prüfen; von Tor (0,8) BFS erreichbare Nachbarzelle aller funktionalen Gebäude; blockierte Platzierung ablehnen. Belegte Anlagen nicht abreißen/verschieben; Inhalt geschützt. Anfang leere Halle. Starter-Setup kann UI durch echte Einzelbefehle durchführen, kein kostenloser Zustand.
